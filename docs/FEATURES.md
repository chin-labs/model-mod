# What your models can do

[繁體中文](FEATURES.zh-TW.md) · [README](../README.md)

- **Streaming and tools.** Text and tool calls stream. Before any output has arrived, HTTP 429, 502, 503, 504 and 529 and other transient errors are retried after 2, 6 and 15 seconds (three retries at most). An integer `Retry-After` of 0–15 seconds raises the next wait to at least that value; a larger value ends the turn immediately with the HTTP status and requested wait. Invalid values and HTTP dates are ignored. Once output has started, a broken stream ends the turn without replaying it.
- **Built-in tools, Skills and MCP.** They work as usual. Built-in tool input schemas come from `toolsFile` when configured; otherwise open object schemas are used and Claude Code validates arguments itself.
- **Subagents and Workflow.** From a subscription session, hand a task to one of your models with the `model-mod:local-worker` agent type (needs `workerModel` or `fallbackModel`), or give a Workflow agent `model: "<your-model-id>"`. A session on one of your models can still delegate to a subscription model; that request uses the subscription.
- **Web search and fetch.** On the API path, `web_search` runs through the API upstream. Codex login uses native web search when `codexWebSearch` (an [advanced option](CONFIGURATION.md#advanced-options)) is on and WebSearch is available in the session. `web_fetch` downloads public HTTP(S) pages itself and checks every DNS answer at each hop, refusing loopback, private, link-local, shared (carrier-grade NAT), multicast, reserved and unspecified addresses, and the host name localhost and names whose last label is local or internal; other special-use ranges are not checked (five redirects at most).
- **Image generation.** `generate_image` saves a PNG in the working directory, by default under `generated-images/`. In a Git repository that file is untracked and binary, so the review gate and the Stop gate end with an `unknown` result (the helper's reason is "An untracked file is binary; review was not performed.") until the file is deleted or ignored by one of the rules that [Delegation and data flow](#delegation-and-data-flow) lists. The API path uses `/v1/images/generations` and a configured image model; Codex login uses its built-in image generation without `imageModel`, on POSIX only. Codex may first read its bundled image-generation skill file from the account directory, which can show one read permission prompt.
- **Codex parent thread reuse.** Eligible requests can reuse a parent; see [privacy and cleanup](LIMITATIONS.md#parent-thread-privacy-and-cleanup).
- **Codex reasoning continuity.** Opaque reasoning items may be retained in memory during tool loops using experimental app-server APIs; replay with a real Codex turn is unverified. Forked requests do not retain reasoning; set `codexThreadReuse` (an [advanced option](CONFIGURATION.md#advanced-options)) to `off` to allow retention. See [limitations](LIMITATIONS.md#codex-login-limitations).
- **Tool search.** `tool_search` finds MCP tools whose schemas were deferred.
- **Status and setup screens.** `/model-mod:status` prints a plain-text report: a title line with the version and the warning count; WARNINGS when there are any (the newest Stop gate warning of the session is listed there too); QUOTA with one block per Codex account (5-hour and weekly bars with percent used and the reset time, relative and local, plus credits and plan); CURRENT PATH (session model, route, account, effort, thread reuse); and DIAGNOSTICS in the groups Picker, one per Codex account and Codex settings; Tools and Prompts appear when an API upstream is configured. Every state is also spelled out (`[OK]`, `[!]`, `[LIMIT]`, `[--]`), so colour is never the only signal; `NO_COLOR` or `TERM=dumb` switches the bars to `#`/`-`. While the quota is read a toast says so and the status line is left alone. A failed quota query shows `無法取得` with its reason and an API upstream shows `沒有額度資料`. `/model-mod:setup` shows its fixed menus in one pane that stays open until setup ends; Esc closes it and cancels: setup then asks nothing more and writes nothing, although a step already running (a model list request, an account logout) finishes first and its result is discarded. Text inputs (endpoint URL, account name, model IDs) stay dialogs, as do menus of more than 12 entries and every menu where no pane can be shown (`-p`, bridge sessions, a body too small); a dialog re-asks when the typed answer is not one of the listed options.
- **Effort.** Claude Code's five levels (`low`, `medium`, `high`, `xhigh`, `max`) are sent as a model suffix such as `model(high)`. For Codex login the helper converts the suffix to app-server effort, including `max`; `effortMode` applies only to the API path. Ultracode is a separate workflow toggle and does not change the level.
- **Compaction.** `/compact` and automatic compaction use your model. A summary keeps what the model keeps; it is not a lossless archive.
- **Images and PDF.** Images are forwarded. A one-page PDF is read as an image.
- **Prompt cache.** API cache usage is passed through; Codex usage is derived from app-server token usage. Cache accounting semantics have not been fully verified.
- **Automatic switch (off by default).** Set `fallbackModel` and, once a turn ends with your subscription usage at `fallbackPercent` (an [advanced option](CONFIGURATION.md#advanced-options)) and a reset time ahead, the session switches to that model with a notice and switches back after the reset. It does not resend the turn that hit the limit, reset any limit or run during a tool loop or in subagents. A manual model change cancels the switch back. While switched, your conversation goes to your upstream. The client saves the switch as your default model for new sessions: a session started while switched also starts on that model, and the session that made the switch saves its previous model again when it switches back. If you close that session before the reset, choose your usual model with `/model`. Whether a session started in the meantime switches back has not been verified.

Codex login also switches to `fallbackModel` when official `rateLimits` reach the configured threshold and a future reset is known. It does not rotate accounts; API upstream models have no official rate-limit switching.

For Codex models, the tool list excludes the mod’s `web_search`; native search activity is shown as one assistant text line per search, not the built-in “Searched” block. The assistant text line was seen once in a real client on one Mac; `generate_image`, `web_fetch` and `tool_search` remain available. Codex automatic compaction items are unsupported; see [limitations](LIMITATIONS.md#codex-login-limitations).

`web_search`, `web_fetch`, `generate_image` and `tool_search` are registered while model-mod is active (`generate_image` with an API image model or a configured Codex account, `tool_search` unless tool search is off), adding up to about 3 KB of tool definitions to requests on subscription models. They refuse calls on subscription models; use Claude Code's built-in tools there. They follow Claude Code's permission rules. How a model behaves is up to the model; this plugin does not make it equal to a subscription model.

## Delegation and data flow

`/model-mod:review` requests a read-only native Codex review; `--base REF` selects a base. `--adversarial` sends a scoped diff, permits focus text after `--` and accepts `--effort`; it excludes untracked files. With `--base REF` only the committed changes `REF...HEAD` are sent, not staged, unstaged or untracked ones; without `--base` the diff against `HEAD`, including staged and unstaged edits, is sent. Native review does not accept focus text or `--effort`. `--gate` requests the structured review described below. `/model-mod:rescue -- TASK` asks Codex for help. Both default to foreground and accept `--account NAME` and `--model ID`. Where supported, `--effort` accepts `low`, `medium`, `high` and `xhigh`. Rescue accepts `--effort`, `--background` and `--write`; native review accepts `--base` and `--background`; adversarial review accepts `--base`, `--effort`, `--background` and focus text; gate accepts `--base` and `--effort`, but not `--background` or focus text. Background jobs are not supported on Windows.

`/model-mod:rescue --write -- TASK` requires interactive confirmation of the working directory. It requests workspace-write for that directory with network access disabled; commands may have other external effects. Background write jobs are limited to one active job per account. Review and ordinary rescue use a read-only sandbox that limits writes and network but **does not restrict reads to the workspace**; commands may read outside it. This differs from the Messages bridge, where the built-in shell is disabled. See [limitations](LIMITATIONS.md#background-delegation-limitations).

Through the user's logged-in Codex CLI, task and focus text and review content go to OpenAI. Adversarial review sends the diff; gate review sends the diff and full contents of untracked, non-ignored files. Untracked files that Git ignores through `.gitignore` files, `.git/info/exclude` or the effective `core.excludesFile` or, when `core.excludesFile` is not set, Git's default user ignore file (under `XDG_CONFIG_HOME`, or `~/.config` by default) are not sent; changes to a tracked file are in the diff even if an ignore rule also matches it. System-level Git config is not read, and of your user-level Git config only the value of `core.excludesFile` is used: other user-level settings, for example a `core.ignoreCase` set only there, are not applied. Git environment variables other than `HOME` and `XDG_CONFIG_HOME` are not read either, so ignore rules defined only in those places are not applied. Native review delegates the target to Codex, which can read files in its sandbox and send what it reads. With the optional Stop gate enabled, an eligible closing turn can send the diff and untracked contents for review; it is off by default. `transfer` imports the current conversation transcript into the selected Codex account after confirmation, where OpenAI persistently stores it. The official CLI handles its own connection; model-mod's delegation path does not use an API proxy or add its own telemetry. The behavior of the CLI and provider, including any telemetry, is outside this project's verification.

Job status and results stay locally in the model-mod state directory under `delegate/v1`, up to 50 records. Finished records older than seven days are removed when the background broker next starts and about hourly while it runs, not on a timer; until then they stay on disk. Results may contain sensitive fragments; local redaction is limited. `/model-mod:cancel ID` stops a job; `/model-mod:jobs --clear` removes finished jobs and results of the current workspace now, but does not delete Codex or provider-side records. Coexistence with the official `openai/codex-plugin-cc` rests on a static source comparison only; see [limitations](LIMITATIONS.md#not-verified). Codex output is untrusted data; gate findings are labeled and control characters are stripped, not independently verified.

## Codex review gate

`/model-mod:review --gate [--account NAME] [--model ID] [--effort E] [--base REF]` requests a structured verdict for the scoped changes, including untracked files. The result shows the account, model, snapshot fingerprint and untrusted findings. `unknown` requires human review; a pass applies only to the same session and snapshot. Gate mode does not accept `--adversarial`, `--background` or focus text. Adversarial review excludes untracked files.

The optional Stop gate is off by default. When enabled, a main-session turn may start an additional read-only Codex review, sending the same data as the gate review (see [Delegation and data flow](#delegation-and-data-flow)) to OpenAI and possibly blocking the end of the turn up to the configured session limit. Read-only commands can still run. After the limit or an unknown result the session may end without a verified pass; review it manually.

## Background Codex delegation

Use `--background` with `/model-mod:review` (except `--gate`) or `/model-mod:rescue` to start a job without waiting. By default it makes no file writes; read-only commands may still run. `/model-mod:rescue --write` enables workspace-write only after an interactive confirmation, in the foreground or background. `/model-mod:jobs [ID] [--all]` lists the current workspace or all workspaces, or inspects one job; `/model-mod:result ID` reads its output, `/model-mod:cancel ID` cancels it, and `/model-mod:jobs --clear` removes finished jobs and results for the current workspace. The one-write-job-per-account limit applies only to background jobs. Combining `--all --clear` clears finished jobs in the current workspace, then lists remaining jobs across all workspaces. IDs may be unique hexadecimal prefixes of at least four characters. Completion notices are best effort.

`/model-mod:transfer [--account NAME]` imports the current session after confirmation and shows a `codex resume` command when completion is confirmed. It does not run a model turn; repeated imports may duplicate the session.
