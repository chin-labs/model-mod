# 合規說明

[English](COMPLIANCE.md)

model-mod 是支援 mod 的程式開發客戶端所用的獨立插件，與 Anthropic 無隸屬關係，也未獲其背書。本頁說明插件如何設計以遵守自己的限制；它不主張任何供應商的條款已授權此用法，也不說明帳號會受到何種處置。**本專案沒有取得此用法的許可。**閱讀適用於你的條款是你自己的責任。

## 插件做什麼、不做什麼

| 規則 | 實際做法 |
|---|---|
| 未修改的客戶端 | 透過插件 hook 運作，不修改客戶端執行檔，也不攔截 TLS。 |
| 不替換端點 | 不設定 `ANTHROPIC_BASE_URL`。訂閱模型與 Remote Control 保留客戶端自身的連線。只有你自己的模型 ID 會透過工作階段的 `ANTHROPIC_CUSTOM_MODEL_OPTION` 準備。 |
| 不碰訂閱憑證 | 不讀取憑證檔、keychain 或訂閱 token，不要求工作階段授權，也不轉送帶驗證的客戶端請求。設定來自客戶端交給插件的插件選項，或來自你以 `MODEL_MOD_CONFIG` 指定的選用設定檔；絕不從客戶端的憑證檔讀取憑證。 |
| 只用你的上游金鑰 | 只送出你提供的上游金鑰，來自插件選項的金鑰透過程序環境與 curl 設定檔傳給 curl，而非命令參數；使用設定檔時，金鑰留在 curl 讀取的標頭檔，命令參數中只有該檔的路徑。 |
| 不接受訂閱服務作為上游 | 拒絕 `anthropic.com`、`claude.ai` 及其子網域的上游主機，也拒絕含帳密、查詢參數或 fragment 的網址。 |
| 只處理你的模型 ID | 處理你選擇的模型或上游列出的模型，加上有效的 worker 或 fallback 模型。含 `claude` 或 `anthropic` 的 ID 與客戶端的官方別名一律不處理。其他模型照常交給客戶端。 |
| 不退回訂閱 | 你的模型的回合或 `/btw` 失敗時，以錯誤訊息結束，絕不改走訂閱重試；本地壓縮失敗也不會改用訂閱產生摘要。 |
| 不偽裝身分 | 回應標示實際的本地模型 ID，不會改標成訂閱模型。 |
| 不直接寫設定檔 | Setup 與 refresh 使用客戶端的設定 API，不直接寫設定檔。客戶端本身可能保存你的設定與最後一次的模型選擇。 |

選用的用量上限切換預設關閉。它只改變之後訊息使用的模型，並在回報的重置時間過後切回；不會重送觸發上限的那一回合，也不會重置任何限制。

## 哪些資料會離開你的電腦

送往你的模型的請求，會把對話、系統指示、工具定義與結果、圖片送到你的上游及其背後的供應商，但不含客戶端工作階段或使用者身分 metadata，也不含訂閱驗證標頭。Web fetch 連線到你指定的網站；圖片生成與搜尋使用你的上游。

客戶端自己發出的部分請求仍可能使用你的訂閱連線：auto 權限分類、未帶名稱的 `/rename`、`Agent(model: 'haiku')`、原生 WebFetch 摘要、`localContext: false` 的 `/context` token 計數，以及 `localTitle: false` 的首提示標題。它們列在[訂閱側請求](LIMITATIONS.zh-TW.md#訂閱側請求)，該表涵蓋已檢查的路徑，不涵蓋所有可能的客戶端請求。金鑰處理與如何從已儲存的預設模型復原，見 [README](../README.zh-TW.md)。

## 上游的條款

model-mod 不提供也不營運上游，金鑰由你持有。支援的上游是 **CLIProxyAPI 搭配你自己登入的 Codex 帳號**。不要將 Claude 帳號或其他不被支援的第三方帳號接到第三方上游。協定相容或測試成功，並不代表任何供應商的條款允許此用法。使用或分享插件前，請閱讀適用於你的客戶端、上游與帳號的現行條款。不得用 model-mod 規避用量限制、轉售或共享帳號，或以訂閱輸出訓練模型。

## 自行檢查

在儲存庫的 clone 中執行：

```bash
claude plugin validate .
claude plugin test .
```

Validate 會列出插件的 hook 與宣告的能力。測試使用假憑證，涵蓋處理哪些模型、被拒絕的設定與不退回訂閱的規則。可閱讀 `hooks/register.ts` 了解端點、金鑰與路由的處理方式。這兩項檢查都不代表法律合規，也沒有涵蓋客戶端發出的每一種請求。
